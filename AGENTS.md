# AGENTS.md

A Cursor plugin marketplace whose single plugin bridges Cursor to a remote MCP server.

## Layout

- `.cursor-plugin/marketplace.json` — marketplace index Cursor reads to discover plugins.
- `plugins/caffeine/` — the published plugin (manifest under `.cursor-plugin/plugin.json`, plus `mcp.json`, `rules/`, `commands/`, `skills/`, `assets/`).
- `scripts/` — repository maintenance scripts (see below).

There is no `package.json`, build step, or bundler; the scripts run directly with Node and use only the standard library.

## Validate

Run the structure check after changing any manifest or plugin component:

```bash
node scripts/validate-template.mjs
```

It exits non-zero and prints errors when something is wrong. What it enforces:

- Plugin and marketplace `name` fields are lowercase (kebab-case; plugin names also allow periods).
- Each plugin manifest has `name`, `displayName`, `version`, `description`; `version` should be semver.
- Files in `rules/`, `commands/`, and skill `SKILL.md` files carry the required YAML frontmatter (`rules` need `description`; `commands` need `name` + `description`; skills need `name` + `description`).
- Manifest path fields point at existing paths that stay inside the plugin.
- Any `mcp.json` defines a non-empty `mcpServers` object with a `url` or `command` per server.

## Check the MCP server

```bash
node scripts/verify-mcp.mjs
```

Walks the MCP discovery/OAuth chain for the server URL in `plugins/caffeine/mcp.json`. It stops before any sign-in, so it needs no credentials. Run from the repository root — it reads `plugins/caffeine/mcp.json` by relative path.

## Test the plugin end to end

```bash
./scripts/dev-install.sh <workspace-dir>            # install
./scripts/dev-install.sh --uninstall <workspace-dir> # remove
```

It symlinks the plugin's rules, commands, and skills into place so edits take
effect on the next Cursor window reload. Note: `mcp.json` is **copied**, not
symlinked, so re-run the script after editing `plugins/caffeine/mcp.json`.

## Conventions

- Scripts are ES modules (`.mjs`, `node:` imports); keep new scripts the same.
- Skills live at `plugins/<plugin>/skills/<name>/SKILL.md`; the skill's own directory name is not used — `dev-install.sh` reads the `name:` from the `SKILL.md` frontmatter.
- To add a plugin, create `plugins/<name>/.cursor-plugin/plugin.json` and register it in `.cursor-plugin/marketplace.json`.
- Do not commit `.cursor/`; it is generated by `dev-install.sh` and gitignored.
